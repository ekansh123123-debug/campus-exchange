# CampusExchange Data Model & State Machines

CampusExchange persists 14 Mongoose models in `backend/src/models/`. Every externally addressable entity uses a human-readable public code generated by `backend/src/services/public-id.service.js` (`CEU-...`, `CEL-...`, `CET-...`, `CER-...`, `CEC-...`, `CEM-...`, `CEV-...`, `CERP-...`, `CEN-...`, `CEA-...`).

## Collections Overview

1. **`User`**: `userCode` (`CEU-...`), `collegeEmail`, `passwordHash` (`select: false`), `role` (`student`, `admin`), `accountStatus` (`active`, `blocked`), `emailVerifiedAt`, `branch`, `academicYear`, `bio`, `ratingAverage`, `ratingCount`, `completedTransactionsCount`.
2. **`EmailVerification`**: `userId`, `email`, `purpose` (`email_verification`, `password_reset`), SHA-256 `codeHash`, `expiresAt`, `attempts`, `maxAttempts`, `consumedAt`.
3. **`RefreshSession`**: `userId`, `tokenHash`, `userAgent`, `expiresAt`, `revokedAt`, `revokedReason`, `replacedByTokenHash`.
4. **`Category`**: `name`, `slug`, `description`, `sortOrder`, `active`.
5. **`Listing`**: `listingCode` (`CEL-...`), `sellerId`, `categoryId`, `title`, `description`, `listingType` (`sell`, `exchange`), `pricePaise`, `condition` (`new`, `like_new`, `good`, `fair`, `for_parts`), `branch`, `academicYear`, `semester`, `subject`, `edition`, `author`, `exchangePreference`, `images`, `status` (`draft`, `pending`, `active`, `reserved`, `sold`, `rejected`, `removed`), `reservedTransactionId`, `moderation`.
6. **`Transaction`**: `transactionCode` (`CET-...`), `txnType` (`sale`, `exchange`), `listingId`, `offeredListingId`, `buyerId`, `sellerId`, `status` (`reserved`, `pending_exchange`, `accepted`, `declined`, `cancelled`, `expired`, `completed`, `disputed`), `notes`, `reservationExpiresAt`, `acceptedAt`, `completedAt`, `handoverConfirmedAt`.
7. **`Conversation`**: `conversationCode` (`CEC-...`), `listingId`, `participantIds`, `buyerId`, `sellerId`, `lastMessageAt`, `lastMessagePreview`.
8. **`Message`**: `messageCode` (`CEM-...`), `conversationId`, `senderId`, `body`, `readByUserIds`.
9. **`Wishlist`**: Compound unique index on `{ userId, listingId }`.
10. **`Review`**: `reviewCode` (`CEV-...`), `transactionId`, `authorId`, `targetUserId`, `rating` (1–5), `comment` (unique compound index on `{ transactionId, authorId }`).
11. **`Resource`**: `resourceCode` (`CER-...`), `uploaderId`, `title`, `description`, `resourceType` (`pyq`, `notes`, `lab_manual`, `syllabus`, `reference`), `branch`, `academicYear`, `semester`, `subject`, `examYear`, `file`, `status` (`pending`, `active`, `rejected`, `removed`), `downloadCount`, `moderation`.
12. **`Report`**: `reportCode` (`CERP-...`), `reporterId`, `targetType` (`listing`, `resource`, `user`, `message`), `targetId`, `targetCode`, `reason`, `details`, `status` (`open`, `in_review`, `resolved`, `dismissed`), `assignedAdminId`, `resolutionNote`.
13. **`Notification`**: `notificationCode` (`CEN-...`), `userId`, `type`, `title`, `message`, `link`, `readAt`.
14. **`AuditEvent`**: `eventCode` (`CEA-...`), `actorId`, `actorRole`, `action`, `targetType`, `targetId`, `targetCode`, `reason`, `metadata`, `requestId`.

## Core State Machines

### Listing Lifecycle
- `draft` → `pending` (seller submits)
- `pending` → `active` (admin approves) or `rejected` (admin rejects)
- `rejected` → `pending` (seller edits & resubmits)
- `active` → `reserved` (buyer reserves a `sell` listing, or seller accepts an `exchange` proposal)
- `reserved` → `active` (transaction cancelled or expired by background job)
- `reserved` → `sold` (seller confirms physical campus handover)
- `draft | pending | active | rejected` → `removed` (seller removes or admin blocks seller)

### Transaction / Handover Lifecycle
- **Sale Listing**: `reserved` (created atomically on `POST /listings/:listingCode/reservations`) → `completed` (seller confirms handover) or `cancelled` / `expired`
- **Exchange Listing**: `pending_exchange` → `accepted` (locks both listings to `reserved`) or `declined` → `completed` (seller confirms handover; marks both listings `sold`) or `cancelled` / `expired`

### Resource Moderation Lifecycle
- `pending` → `active` (admin approves)
- `pending` → `rejected` (admin rejects)
- `active` → `removed` (admin takedown after report or policy review)
